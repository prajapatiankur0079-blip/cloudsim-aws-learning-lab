MODULE 01 · FOUNDATION

Cloud Computing Fundamentals

What is cloud computing?

Cloud computing means using computing resources—such as servers, storage, databases and networking—over a network when you need them. Instead of buying and maintaining every physical server yourself, you can rent resources from a cloud provider.

Why do companies use cloud?

  • On-demand: create resources when required.
  • Scalability: increase or decrease capacity with workload.
  • Pay for usage: charges depend on the service and its pricing model.
  • Global reach: deploy services in different geographic regions.
  • Managed services: providers can handle some infrastructure maintenance.

Service models

  • IaaS: virtual infrastructure such as virtual machines and networks.
  • PaaS: a managed platform for building and running applications.
  • SaaS: complete software delivered to users over a network.

Regions and Availability Zones

A Region is a separate geographic area. An Availability Zone is an isolated location within a Region. Using multiple Availability Zones can improve availability when an application is designed for it.

User → DNS → Application → Compute → Database / Storage
Real-world example: An online shop may run its application on compute instances, store product images in object storage, and keep orders in a database.

Check your understanding

What is the main difference between scalability and availability?

Scalability means adapting capacity to workload. Availability means keeping a service accessible when users need it.
MODULE 02 · NETWORKING

VPC, Subnets, Routing, IGW and NAT

What is a VPC?

A Virtual Private Cloud is a logically isolated virtual network in AWS. You select an IP address range and place supported resources inside it.

What is CIDR?

CIDR represents an IP network and its prefix length. For example, 10.0.0.0/16 represents a larger IPv4 network than 10.0.1.0/24. A subnet's CIDR must fit inside its VPC range and must not overlap another subnet in that VPC.

Public vs private subnet

A subnet is commonly called public when its route table provides a path to an Internet Gateway. A private subnet normally has no direct route to an Internet Gateway. Public IP assignment and security rules also affect actual reachability.

Internet Gateway (IGW)

An Internet Gateway connects a VPC to the internet when the required routes, public addressing and security rules are configured. Attaching an IGW alone does not make every resource publicly reachable.

NAT Gateway

A NAT Gateway allows resources in a private subnet to initiate supported outbound IPv4 connections to external destinations without accepting unsolicited internet-initiated connections through that NAT path.

Private EC2 → Private Route Table (0.0.0.0/0 → NAT) → NAT Gateway in Public Subnet → Public Route Table (0.0.0.0/0 → IGW) → Internet

Route table

A route table contains destination networks and targets. The most specific matching route is used. The default IPv4 route is 0.0.0.0/0.

Security Group vs Network ACL

  • Security Group: stateful traffic rules associated with supported resources or network interfaces.
  • Network ACL: stateless subnet-level rules; inbound and outbound traffic are evaluated separately.
Common troubleshooting order: check subnet CIDR → route-table association → target route → IGW/NAT setup → public IP where needed → security rules → service listening port.

MODULE 03 · COMPUTE

Amazon EC2 and Virtual Servers

What is EC2?

Amazon EC2 provides virtual compute instances. You select an image, instance type, network configuration, storage and security settings.

  • AMI: a template used to launch an instance, including an operating system and other configured software.
  • Instance type: determines available CPU, memory, networking and other capabilities.
  • EBS volume: block storage that can persist independently of an instance, subject to its configuration.
  • Security Group: controls permitted network traffic.
  • User Data: can run bootstrapping commands during instance launch, depending on the operating system and configuration.

Instance lifecycle

Choose AMI → Configure instance → Launch → Running → Stop / Start / Terminate

Stopping and starting an instance is different from terminating it. Termination removes the instance; attached storage behavior depends on its deletion settings.

Practice: use the local EC2 lab to create a simulated instance, stop it, start it and inspect its state. No real EC2 instance is created by this local action.

MODULE 04 · STORAGE

S3, EBS and EFS

Amazon S3 — Object storage

S3 stores objects in buckets. An object has data and metadata and is identified by a key within its bucket. Typical uses include backups, images, static files, logs and data archives.

Amazon EBS — Block storage

EBS provides block volumes commonly attached to EC2 instances. It is suitable for operating-system disks, application data and workloads that need block-level storage.

Amazon EFS — File storage

EFS provides managed shared file storage that supported compute resources can mount concurrently.

S3 = Objects and keys | EBS = Disk blocks | EFS = Shared file system
Remember: storage type should be chosen according to access pattern, durability needs, performance, sharing requirements and cost.

MODULE 05 · SECURITY

IAM, Roles, Policies and KMS

What is IAM?

Identity and Access Management controls who can access AWS resources and which actions they can perform. Policies describe permissions and can be attached to identities or resources where supported.

Users, groups and roles

  • User: an identity for a person or workload that needs long-term IAM identity credentials where appropriate.
  • Group: a way to manage permissions for a collection of IAM users.
  • Role: an identity with permissions that can be assumed by a trusted principal to obtain temporary credentials.

Least privilege

Give only the permissions needed for the task. Avoid broad permissions such as unrestricted administrator access for everyday work. Review and remove permissions that are no longer required.

KMS

AWS Key Management Service helps create and manage cryptographic keys used to protect data. Key policies and permissions affect who can use keys.

Security basics: never commit secrets or private keys to GitHub; avoid hardcoding credentials; protect SSH private keys; use MFA where appropriate; and review access regularly.

MODULE 06 · LINUX

Linux Essentials for Cloud Engineers

Linux is widely used for servers, containers and cloud workloads. Learn to navigate files, inspect processes, read logs and understand permissions.

  • pwd — print the current directory.
  • ls -la — list files, including hidden files.
  • cd /path — change directory.
  • mkdir project — create a directory.
  • cp source destination — copy a file.
  • mv old new — move or rename a file.
  • grep "error" app.log — search text in a log.
  • tail -f app.log — follow new log lines.
  • ps aux — inspect processes.
  • df -h — inspect filesystem space.
  • free -h — inspect memory usage.
  • chmod — change file permission bits.

Permission example

In chmod 640 file.txt, the owner gets read/write, the group gets read, and others get no permissions. Use permission changes carefully, especially on server configuration and secret files.

Logs troubleshooting flow

Confirm the symptom → Check service status → Read logs → Inspect ports and resources → Test again after one change
Practise these commands in your Ubuntu WSL environment before using them on a production server.
MODULE 07 · DEVELOPER TOOLS

Git, GitHub and Docker

Git vs GitHub

Git is a version-control tool that tracks changes to files. GitHub is a hosting and collaboration platform for Git repositories. Git keeps a history of changes; GitHub helps share code, review changes and collaborate.

  • git status — inspect working-tree changes.
  • git add . — stage current changes; inspect files first to avoid staging secrets.
  • git commit -m "message" — create a local commit.
  • git push — send commits to a configured remote.
  • git pull — fetch and integrate remote changes according to configuration.

What is Docker?

Docker packages an application and its dependencies into an image that can run as a container. Containers share the host kernel but are isolated using operating-system features; they are not full virtual machines.

Application + Dependencies → Docker Image → Container → Logs / Ports / Volumes
  • Image: the packaged template.
  • Container: a running or stopped instance of an image.
  • Dockerfile: instructions for building an image.
  • Volume: storage used to persist or share data beyond a container's writable layer.
  • Port mapping: makes a container service reachable through a host port.

GitHub stores and shares source code; Docker packages software and its runtime dependencies. They solve different problems and are commonly used together.

MODULE 08 · AUTOMATION

CI/CD and Jenkins

Continuous Integration (CI) means integrating code changes frequently and running automated checks. Continuous Delivery or Deployment automates preparing or releasing tested changes.

Typical pipeline

Developer Push → Git Repository → Jenkins Pipeline → Build → Automated Tests → Package Image → Deploy → Verify

What does Jenkins do?

Jenkins automates workflows through jobs and pipelines. A pipeline can check out source code, install dependencies, run tests, build an artifact and deploy it to an environment.

  • Store pipeline definitions in version control where practical.
  • Keep credentials in a secrets mechanism, not source code.
  • Fail the pipeline when required tests fail.
  • Check logs and return codes when a stage fails.
  • Use approvals and rollback plans appropriate to the environment.
A successful build does not automatically mean a safe deployment. Validate configuration, access, tests, health checks and rollback procedures.
MODULE 09 · OPERATIONS

CloudWatch, CloudTrail and Troubleshooting

CloudWatch

CloudWatch is used for monitoring through metrics, logs, dashboards and alarms. Metrics are measurements; logs are event records. An alarm can change state when a configured condition is met.

CloudTrail

CloudTrail records supported AWS account activity and API events, helping investigate which principal performed an action and when.

Incident troubleshooting method

  1. Define the problem and its impact.
  2. Identify what changed recently.
  3. Check service status, logs, metrics and permissions.
  4. Test network connectivity, DNS, routes and ports as appropriate.
  5. Make one controlled change at a time.
  6. Verify recovery and document the root cause.
Example: If a web page times out, investigate DNS resolution, network routes, firewall rules, server health and whether the application is listening on the expected port. Do not assume every timeout is a DNS problem.
MODULE 10 · CAREER

Cloud Engineer Interview Practice

Question 1: What is the difference between a public and private subnet?

A public subnet has a route to an Internet Gateway. A private subnet generally does not have direct IGW routing. Actual internet reachability also depends on addressing, security rules and other configuration.

Question 2: What is the difference between S3 and EBS?

S3 is object storage accessed through APIs. EBS provides block volumes commonly attached to EC2 instances. They differ in access method, use cases and performance characteristics.

Question 3: Why use Docker?

Docker packages an application with its dependencies into an image so it can run in a more consistent container environment across supported systems.

Question 4: What is least privilege?

It means granting only the permissions needed to perform a task and avoiding unnecessary access.

Question 5: How would you troubleshoot a server that is unreachable?

Check the instance state, addressing, routes, security rules, network ACLs where relevant, listening service, operating-system firewall and logs. Test each layer systematically.
Daily method: study one concept, explain it aloud in your own words, perform one safe practical exercise, then answer two interview questions without looking at the notes.

Amazon EC2: Virtual Servers in the Cloud

Learn the architecture, components, instance lifecycle, networking, storage, security and troubleshooting of Amazon Elastic Compute Cloud (EC2).

All practical actions in the linked CloudSim lab are local simulations. They do not create real AWS resources.

1. What is EC2?

Amazon Elastic Compute Cloud (EC2) is an AWS service that provides virtual servers called instances. An instance can run an operating system and applications such as websites, APIs, databases or background workers.

  • Elastic: you can change capacity as application needs change.
  • Compute: CPU and memory resources run your software.
  • Cloud: you provision and manage infrastructure through AWS interfaces and APIs.
Example: A company can run its web application on an EC2 instance instead of purchasing and maintaining a physical server.

2. EC2 architecture and structure

This simplified diagram shows how an internet request may reach an EC2-hosted application. Actual connectivity depends on routing, addressing and security configuration.

How a request reaches the application

  1. A user requests the application's public endpoint.
  2. The Internet Gateway provides a path between the VPC and the internet when routing is configured.
  3. The subnet route table determines where traffic is directed.
  4. Security Groups allow or deny traffic according to their rules.
  5. The EC2 instance receives permitted traffic and the application responds.
Important: A public subnet alone does not make an instance reachable. Routes, public addressing, security rules, host firewall and a listening application may all matter.

3. Important EC2 components

Amazon Machine Image (AMI)

An AMI is a template used to launch an instance. It specifies the operating system and may include preconfigured software and settings.

Instance type

The instance type determines available compute resources, including CPU, memory, networking and other capabilities. Choose a type based on workload requirements.

Key pair

A key pair can support secure login to instances. Keep private keys secret and use an appropriate access method for the operating system and configuration.

Security Group

A Security Group acts as a virtual firewall for supported resources. It is stateful and controls permitted inbound and outbound traffic.

Storage

EC2 can use EBS block volumes and instance store where supported. Separate object storage such as S3 is useful for files, backups and application assets.

4. Instance lifecycle

  1. Launch: create an instance from an image and selected configuration.
  2. Running: the instance is operating; compute charges may apply in real AWS.
  3. Stop: for supported EBS-backed instances, compute billing generally stops, but storage and other resources may still incur charges.
  4. Start: restart a stopped instance; its public IPv4 address may change unless a persistent address is configured.
  5. Reboot: restart the operating system without the same lifecycle effect as stop/start.
  6. Terminate: permanently end the instance. Data on volumes may be affected depending on volume settings.
Cost safety: CloudSim simulates these actions locally. Before using real AWS, verify current pricing and inspect attached resources to avoid unexpected charges.

5. Networking and access

  • A VPC is a logically isolated network in AWS.
  • A subnet places resources within a VPC address range and Availability Zone.
  • Route tables determine the next hop for network traffic.
  • An Internet Gateway supports internet connectivity for appropriately routed resources.
  • Security Groups filter traffic at the resource level; network ACLs operate at the subnet level.
  • SSH commonly uses TCP port 22 for Linux; RDP commonly uses TCP port 3389 for Windows. Do not expose administration ports broadly.

6. Troubleshooting an unreachable EC2 server

  1. Confirm the instance state and correct IP address or DNS name.
  2. Check the route table, subnet and internet gateway path where relevant.
  3. Check Security Group inbound and outbound rules and network ACLs.
  4. Confirm the operating-system firewall permits the required traffic.
  5. Verify the application or SSH service is running and listening on the expected port.
  6. Review system and application logs; change one thing at a time and retest.

Useful Linux commands when you have access to the server:

  • ip route — inspect the routing table.
  • ss -tuln — inspect listening TCP/UDP sockets.
  • systemctl status ssh — inspect SSH service status on systems using that service name.
  • curl -I http://localhost:PORT — test a local HTTP endpoint, replacing PORT with the actual port.

7. Interview practice

Q1. What is an AMI?

An AMI is a template used to launch EC2 instances. It contains information needed to start an instance, including an operating-system image and, depending on the AMI, preconfigured software.

Q2. What is the difference between stopping and terminating an instance?

Stopping an instance pauses it so it can generally be started again. Terminating an instance permanently ends it. Storage retention depends on volume configuration and other resource settings.

Q3. Why might an EC2 instance be unreachable?

Possible causes include an incorrect address, missing route, incorrect Security Group or network ACL rules, host firewall settings, or a service that is not listening. I would check each layer systematically.

Q4. What is a Security Group?

A Security Group is a stateful virtual firewall associated with supported AWS resources. Its rules determine which inbound and outbound traffic is permitted.
